## 三、逐项详述

### P1（高 · 核心功能不可用 / 并发正确性 / 数据完整性）

**AL-01 重置密码必 404**
- 触发：主管"用户管理→重置密码"提交 `POST /users/{id}/reset_password`；后端 `users.py` 仅 `GET/POST ""`、`PUT /{id}`，无该端点 → FastAPI 404。
- 影响：重置密码功能不可用；前端单测用 mock 固化 URL，未暴露。
- 修复：后端 `users.py` 补 `POST /users/{id}/reset_password`（校验 `password`→`hash_password`）；或前端改用 `PUT /users/{id}` 携带 `password`（`UserUpdate` 已支持）。

**AL-02 统计报警明细表坏**
- 触发：`Stats.jsx` `fetchAlarmDetails().then(setAlarms)`，后端 `/api/stats/alarms` 返回 `{total,items}`，`dataSource={alarms}` 传对象。
- 影响：Table 按数组处理对象 → 明细表渲染异常/为空。
- 修复：`setAlarms(r.items || [])`；单测用 mocked `{total,items}` 结构固化。

**AL-03 模拟报警填场景必 422**
- 触发：Monitor 的 `scene` 用 `Select mode="tags"` 提交数组，后端 `AlarmSimulate.scene: Optional[str]`。
- 修复：改单选 + 提交取 `scene[0] ?? undefined`（或后端放宽为 `Union[str,list]`，推荐改前端）。

**AL-04 火灾类型 `other` 读写不一致**
- 触发：`constants.FIRE_TYPES` 含 `other`，报警 `simulate` 后端仅 `electrical/ordinary/oil`（预案侧才含 other）。
- 修复：统一枚举（抽公共常量）；报警模拟场景下拉过滤 `other`，或后端 simulate 也接受 `other`，并与预案对齐。

**AL-05 并发确认真实重复处置单**
- 实测：双路并发 confirm(true)，10 轮中 5 轮产生 2 张处置单。
- 根因：`if emergency is None` 检查后插入，无 DB 唯一约束/无写锁串行。
- 修复：`Emergency.alarm_id` 建 DB 唯一约束（IntegrityError→409）；`confirm` 加 `pending→confirmed` 条件更新并断言 rowcount（幂等）。

**AL-06 并发异常巡检重复维修单**
- 实测：双路并发提交 abnormal，6 轮 2 轮产生 2 张维修单（patrol_id 重复）。
- 修复：`repairs.patrol_id` 唯一/部分索引；`submit_result` 的"查 active→insert"置于同一事务条件写。

**AL-07 预案并发重复（DB 无唯一约束）**
- 实测：并发建同 (area,fire_type) 双 200、两条都入库；顺序建已被应用层 409 拦，并发绕过。
- 修复：`plans(area_id, fire_type)` 建部分唯一索引（`WHERE fire_type IS NOT NULL`），捕获唯一冲突返回 409。

**AL-08 SQLite 外键未启用 + 删除产生孤儿**
- 实测：`PRAGMA foreign_keys=0`；删除"有巡检/维修但无报警"的设备返回 200，patrol/repair 的 `device_id` 悬空；删预案使 `linkage_runs.plan_id` 置 NULL 失溯。
- 修复：连接启用 `foreign_keys=ON` + `timeout`；`delete_device` 增查 Patrol/Repair 引用（有则 409 或级联）；`delete_plan` 有联动记录则 409 或软删/冗余 `plan_name`；对关联外键显式 `ondelete` 策略。

### P2（中 · 一致性 / 健壮性）

**AL-09 确认真实的现场描述不落库**：`AlarmConfirm` 无 `scene` 字段→被 pydantic 丢弃，前端必填项浪费。修复：schema 增 `scene: Optional[str]`，确认时 `alarm.scene = body.scene or alarm.scene`。

**AL-10 报警确认无状态守卫**：已确认真实后再改判误报，旧的 active 处置单残留。修复：`confirm` 开头校验 `alarm.status=="pending"`（否则 409/幂等）；如实→误改判时级联关闭既有处置单并原子提交。

**AL-11 巡检/维修状态机过松**：`finish` 可重复/可对 pending 触发，`start` 可改回；并发 last-write-wins。修复：`submit_result` 限 pending、`start` pending→in_progress、`finish` in_progress→done（否则 409/幂等），用条件更新断言 rowcount。

**AL-12 设备搜索只搜当前页、分页错乱、请求过频**：后端无 `keyword`，前端仅滤当前页 data。修复：后端 `list_devices` 增加 `keyword`（name/device_no/area 模糊），前端并入 params、去掉本地二次过滤，输入加防抖。

**AL-13 时间显示偏 8 小时**：后端存 naive-UTC 无时区标记，前端 `new Date(...)` 按本地解析。修复：前端统一按"该值即 UTC"换算后显示，或后端输出带偏移；`alarm_trend` 分桶同步对齐。

**AL-14 预案保存无 ≥1 动作前端校验**：被后端 400。修复：保存前校验 `validActions.length>0` 并提示。

**AL-15 确认真实后设备复原闭环缺失**：设备长期 `alarm`，依赖人工建维修单。修复：确认真实自动生成关联维修单，或提供 `alarms/{id}/resolve` 复原接口。

**AL-16 JWT 密钥未持久化**：未设 env 时每进程随机 → 多 worker/重启 token 失效。修复：生产强制 `FIRE_ALARM_SECRET`；文档化生成/轮换；可缩短 24h 过期。

**AL-17 SQLite 写锁风险**：未开 WAL/未设 busy_timeout。修复：`journal_mode=WAL` + `busy_timeout` + `timeout`，对 `OperationalError` 重试。

**AL-18 登录限流误伤合法用户**：窗口内成功登录也被计数、历史失败计入。修复：同窗口内成功登录即重置该 key；仅对失败计数。

**AL-19 响应信封不统一**：裸 list / {total,items} / {ok} / 业务 dict 混用。修复：定义通用分页信封 `Page[T]={total,items}`、集合统一 `{items}`、写接口统一资源体或 `{ok}`，用 `response_model` 约束。

**AL-20 Monitor 加载三态不全 + 轮询无取消**：加载失败无错误态；3s 轮询无取消/隐藏暂停。修复：加 `error` state/提示；`AbortController`/`visibilitychange` 暂停；卸载清理定时器与 in-flight。

- **AL-21** Linkage/Emergencies 详情拉取加 `try/catch + message.error`。
- **AL-22** Devices/Plans/Repairs/Users 提交入口加进行中禁用（`loading/confirmLoading`）防重复。
- **AL-23** 坐标 `d.x ?? 20`（保留 0）。
- **AL-24** 预案 enabled `initialValue={true}` 对齐提交。
- **AL-25** token 存 sessionCookie–加固 + 启动 `/auth/me` 校验恢复登录态。
- **AL-26** 用 `Form.useForm()` 实例替换 `window.__loginForm`。
- **AL-27** 列表查询加 `joinedload/selectinload` 预加载关联，消 N+1。
- **AL-28** `execute_linkage` 只 flush 不 commit，由调用方统一 commit。
- **AL-29** `_validate_actions` 校验 `action_type in ACTION_TYPES`。
- **AL-30** （可选）读接口按角色/范围隔离；共享消防数据当前可接受。

## 四、已验证 OK 要点（未重复上报）

- **RBAC 全覆盖**：users/devices/plans 写仅 supervisor；alarms/emergencies duty+supervisor；patrols/repairs maintenance+supervisor；stats 仅 supervisor；simulate 仅 duty/supervisor；`/api/stats/alarms` 已收口（实测 duty→403）。
- **注入面**：全程 ORM 参数化，无 SQL/命令注入；前端无 `dangerouslySetInnerHTML`/`innerHTML`/动态用户 `href`。
- **质量/敏感**：密码 bcrypt；`UserOut` 不泄漏哈希；无敏感日志；导出有公式注入清洗（`= + - @`）。
- **Mass assignment**：update 仅 schema 声明字段，无法借多余字段改 `role/is_active`。
- **枚举/时间契约（除既定项）**：device_type/status/action_type/patrol/repair/alarm status、`YYYY-MM-DD` 日期、分页 `{total,items}`（devices/alarms/linkage）读钳制等基本对齐。
- **分页/除零/安全头/CORS/生产关 docs** 均已修复并覆盖。
- **端到端全流程**（新账号：建户→登录→设备→模拟报警→自动联动4动作→确认真实→处置→闭环→异常巡检→维修→完成→演练→统计导出）顺过渡、计数一致。
- **容错**：孤儿设备/孤儿报警、重复 close（幂等）、空导出、超大/负分页、非法枚举、`get_matching_plan` general/首个兜底，均结构化响应、不 500。
